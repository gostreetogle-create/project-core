## 2026-06-01 — Первая сессия

### Проблема пользователя

Пользователь ~6 месяцев пытается создать CRM/PLM/ERP систему для малого производства. Проекты постоянно срываются из-за:
- UI-слой ломает логику при изменениях
- AI-агенты (Cursor и др.) переписывают код по кругу
- Нет единой архитектуры — каждый проект начинается заново
- Контекст теряется при обрыве связи AI

### Решение: Project Brain

Создана система **project-brain** — портативная папка, содержащая:
1. **STARTUP.md** — инструкция для AI-агента: «прочитай и сделай»
2. **incoming/** — сюда клонируются репозитории для анализа
3. **knowledge-base/** — выходные данные (анализ проектов + векторная БД)
4. **prompts/** — системные промты и методология анализа

### Архитектура решения

```
Пользователь → клонирует репозитории в incoming/
            → говорит AI: "читай STARTUP.md и делай"
            → AI анализирует проекты
            → AI сохраняет знания в knowledge-base/
            → AI задаёт вопросы через QUESTIONS.md
            → AI создаёт чистое ядро для новых проектов
            → Копирование папки на другой ПК = полный перенос
```

### Технологический стек (утверждён)

| Слой | Выбор |
|------|-------|
| Frontend | Angular + PrimeNG (через kp-* обёртки) |
| State | Signals (без NgRx) |
| Backend | Express.js + MongoDB + Mongoose |
| Auth | JWT (access + refresh) |
| UI Kit | kp-* компоненты (обёртки над PrimeNG) |
| Стили | SCSS + CSS-переменные (токены) |
| Тесты | Vitest |
| Контейнеры | Docker Compose (MongoDB + backend) |

### Ключевые принципы архитектуры

1. **Строгие слои:** core → shared → features → layout (только в одну сторону)
2. **Standalone компоненты** (без NgModules)
3. **inject()** вместо constructor DI
4. **OnPush** change detection
5. **Только kp-* компоненты** на страницах (никакого прямого PrimeNG)
6. **CRUD Factory** — один generic-роутер для всех сущностей
7. **FreezeGuard** — блокировка завершённых модулей (frozen/locked/wip/deprecated)
8. **Чистое ядро:** без бизнес-логики, только инфраструктура
