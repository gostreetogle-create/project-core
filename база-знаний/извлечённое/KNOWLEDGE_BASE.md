## 1. ЦЕЛЬ ПРОЕКТА

Создать **универсальное ядро (project-core)** для быстрого запуска веб-приложений (CRM/PLM/ERP).
Ядро — это чистый фундамент без бизнес-логики. На его основе AI-агент создаёт конкретный сайт.

### Проблема, которую решаем
- UI-слой ломает логику при изменениях → **строгие слои с зависимостями только в одну сторону**
- AI-агенты переписывают код по кругу → **FreezeGuard (блокировка готовых модулей)**
- Каждый проект начинается с нуля → **единое ядро с лучшими практиками из 8 предыдущих проектов**
- Контекст теряется при обрыве связи → **SESSION_LOG.md + KNOWLEDGE_BASE.md + чек-листы**

## 3. АРХИТЕКТУРА

### 3.1 Слои (строго!)

```
core → shared → features → layout
(ядро)  (общее)  (страницы)  (оболочка)
```

- **core/** — сервисы. Не знает про страницы и layout
- **shared/** — UI-компоненты (kp-*), типы, утилиты. Не знает про страницы
- **features/** — страницы. Не зависят друг от друга (lazy loading)
- **layout/** — оболочка (сайдбар, топбар). Знает про всё

### 3.2 Стандарты кода (инварианты)

Обязательно:
- ✅ Standalone компоненты (никаких NgModules)
- ✅ `inject()` вместо constructor DI
- ✅ Signals вместо NgRx
- ✅ OnPush change detection
- ✅ `strict: true` в TypeScript
- ✅ Только SCSS (без inline-стилей)
- ✅ Только kp-* компоненты на страницах (без прямого PrimeNG)
- ✅ Русский язык в интерфейсе
- ✅ `unknown` вместо `any` + type guard

Запрещено:
- 🔴 `any` (только `unknown` + type guard)
- 🔴 constructor DI (только `inject()`)
- 🔴 NgModules (только Standalone)
- 🔴 NgRx (Signals достаточно)
- 🔴 Inline-стили (только SCSS)
- 🔴 Прямой PrimeNG на страницах (только через kp-*)
- 🔴 Секреты в коде (только .env)
- 🔴 axios (native fetch)

### 3.3 FreezeGuard

Система блокировки файлов для защиты готового кода:

| Статус | Маркер | Что значит |
|--------|--------|------------|
| frozen | 🧊 | Заморожено. Редактировать только с разрешения |
| locked | 🔒 | Заблокировано. Не трогать |
| wip | 🚧 | В разработке. Можно менять |
| deprecated | 🗑 | Устарело. Будет удалено |

## 5. UI KIT (kp-* компоненты)

Каждый компонент — обёртка над PrimeNG. На страницах используется только kp-*.

| Компонент | Селектор | Описание |
|-----------|----------|----------|
| Кнопка | `<kp-button>` | Основная, второстепенная, опасная, текстовая, loading |
| Поле ввода | `<kp-input>` | Текст, число, пароль, email, float label |
| Выпадающий список | `<kp-select>` | Выбор из списка, поиск, очистка |
| Карточка | `<kp-card>` | Блок с заголовком |
| Таблица | `<kp-table>` | CRUD + пагинация + сортировка + действия |
| Диалог | `<kp-dialog>` | Модальное окно |
| Уведомление | `<kp-toast>` | Всплывающие сообщения |
| Подтверждение | `<kp-confirm-dialog>` | Подтверждение действий |
| Бейдж | `<kp-badge>` | Цветная метка статуса |
| Хлебные крошки | `<kp-breadcrumb>` | Навигационный путь |

## 6. ЗАПУСК ПРОЕКТА

### На новом компьютере (Windows)
```powershell
git clone <repo-url> my-project
cd my-project
.\start.ps1
```
Что делает `start.ps1`:
1. Проверяет Node.js
2. Устанавливает зависимости (npm install), если нет node_modules
3. Проверяет Docker → запускает MongoDB контейнер (или использует существующий)
4. Освобождает порты 3000 и 4200 (убивает процессы, которые их заняли)
5. Запускает backend (Express на порту 3000)
6. Запускает frontend (Angular на порту 4200)
7. Открывает браузер

### Деплой на сервер (Ubuntu)
```bash
./deploy.sh
```
Что делает `deploy.sh`:
1. Pull из git
2. Собирает frontend + backend
3. Запускает Docker Compose
4. **НЕ трогает MongoDB данные** (volume защищён)
5. **НЕ трогает uploads** (фотографии сохраняются)
6. Проверяет healthcheck backend

## 8. СОЗДАНИЕ НОВОГО ПРОЕКТА ИЗ ЯДРА

Процесс (для AI-агента):

1. **Инициализация**
   - Скопировать папку project-core → new-project
   - Удалить .git
   - Настроить .env
   - Инициализировать новый git

2. **Бизнес-логика**
   - Прочитать `BUSINESS_LOGIC_RU.md`
   - Если вопросы — задать пользователю
   - Записать решения в CHANGELOG.md

3. **Реализация (послойно)**
   - Модели данных (Mongoose)
   - CRUD роутеры (createCrudRouter)
   - Сервисы на фронте (api.service.ts)
   - Страницы (список → создание → редактирование)
   - Тесты (Vitest)
   - Документация

4. **Финализация**
   - `ng build` — проверка сборки
   - Запуск тестов
   - `git init + commit`

**Защита от потери контекста:** Каждый этап записывается в CHANGELOG.md с статусом:
- `[x]` — выполнено
- `[ ]` — ожидает
- `[?]` — требует уточнения
